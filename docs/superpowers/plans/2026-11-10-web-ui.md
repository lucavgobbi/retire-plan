## 1. Ground truth: engine contract (as read from source, 2026-11-10)

Everything below is **actual current code**, not spec guesses. The UI builds on exactly
this.

- `simulate(plan, scenario, returns, tables?)` → `SimulationResult` (`src/simulate.ts`).
  Throws on `validatePlan` errors — the UI must show plan-level errors *before* running.
  `tables` defaults to the bundled `ca-2026.json`; the app does not need to load tables.
- `buildDeterministicReturns(assumptions, startAge, endAge)` → `ReturnSeries`
  (`src/returns/deterministic.ts`).
- `runMonteCarlo(plan, scenario, tables)` → `{ successRate, percentileNetWorth, sampleFailureAge }`
  — **not consumed by UI in Phase 2.**
- `types.ts` plan types (verbatim field names for forms):
  - `profile: { birthYear, currentAge, province: "ON", endAge }`
  - `accounts: { id, type: "tfsa"|"rrsp"|"nonreg", balance, assetMix: {equity,bond,cash} }`
  - `assets: { id, kind: "primary-home"|"other", name, value, appreciationRate, sellEvent?: {age, costsPct} }`
  - `debts: { id, kind: "mortgage", rate, termYears, amortizationYears, balance, monthlyPayment }`
  - `incomes: { id, kind: "employment"|"cpp"|"oas"|"other", annualAmount, startAge, endAge?, raiseRate }`
  - `expenses: { id, name, annualAmount, startAge, endAge?, inflationRate }`
  - `savingsPolicy: { id, priority, target: "rrsp-match"|"rrsp"|"tfsa"|"nonreg"|"mortgage-prepay", perYearCap?, untilAge?, matchRate? }`
  - `validatePlan(plan) → string[]` (empty = valid).
- `Scenario`: `{ id, name, simMode, retirementAge, returnAssumptions: {equity,bond,cash},
  withdrawalOrder: AccountType[], mcConfig? }` — **flat. No `basePlanId`, no `overrides`,
  no `perYearOverrides`** (spec §2 sketched deltas ("scenarios as deltas"); the engine
  chose a concrete scenario). Deltas are an app-layer concept (Task 2).
- `YearResult` fields → the projection table's columns (Task 6 uses these verbatim):
  `age, year, income{employment,cpp,oas,gis,other}, taxableIncome,
  tax{federal,provincial,surtax,oasClawback,total,marginalRate},
  withdrawals{tfsa,rrsp,nonreg}, contributions{tfsa,rrsp,nonreg},
  savings{tfsa,rrsp,nonreg,mortgage}, expenses, shortfall,
  balances{tfsa,rrsp,nonreg,home,debt}, netWorth, tfsaRoom, rrspRoom, events[], warnings[]`.
  (Spec §3 sketch mentioned `expensesAfterTax` and `benefits`; the engine landed
  `expenses` + tax-inclusive flows — follow `types.ts`.)
- `SimulationResult.summary`: `{ success, failureAge?, finalNetWorth, worstShortfallAge? }`
  → drives the "plan fails at age N" banner.
- Engine `IncomePlan.kind` has **no `"gis-eligible"`** (spec's early sketch dropped it;
  GIS eligibility is evaluated by the stepper). Forms must not render that kind.
- Known v1 simplifications already documented in `docs/assumptions.md` (mortgage rate
  convention, uniform ON indexation, GIS exemption, ACB model, etc.) — the Assumptions
  view (Task 9) mirrors this file's content.
- **Audited-and-in-remediation surfaces** (do not treat as stable until the gate clears —
  see §0.1b): `src/accounts/flows.ts` (prepay terminal-cash case), `src/accounts/nonreg.ts`
  (ACB seeding via a prospective optional `AccountPlan.bookValue?: number`), and
  `data/tax/ca-2026.json` RRIF minimum factors (later-age values reported wrong by the
  validator). The UI never re-derives these rules; it consumes `SimulationResult` output,
  so remediation lands here without UI redesign — only the form field (Task 5), the sample
  copy (Task 3), and the assumptions registry (Task 9) need re-sync.

**Derived determinism note:** the engine is deterministic (mulberry32 seeding, closed
inputs); `runDeterministic(plan, scenario)` below is a pure function. UI reruns produce
byte-identical results for identical inputs, and the projection must not mutate emitted
results.

## 2. App-layer decisions (reasonable defaults, per handoff authorization)

- **Charts:** Recharts (spec §2 "Recharts or equivalent"). One chart library only.
- **State:** React Context + `useReducer`; no Redux/Zustand.
- **Persistence:** native IndexedDB with a small promise wrapper; storage logic isolated behind a
  `StorageProvider` interface so tests swap an in-memory adapter (no `fake-indexeddb`
  dependency).
- **Scenario delta model (spec "scenarios as deltas", engine-flat reality):**
  ```ts
  interface ScenarioDelta {
    id: string; name: string; basePlanId: string;
    simMode: "deterministic";               // mc/historical queued Phase 3, stored but disabled
    mcConfig?: Scenario["mcConfig"];        // stored for Phase 3; not editable in Phase 2
    overrides: {
      retirementAge?: number;
      returnAssumptions?: { equity: number; bond: number; cash: number };
      withdrawalOrder?: AccountType[];
    };
  }
  function resolveScenario(delta: ScenarioDelta, active: Scenario | undefined,
                           defaults: { retirementAge: number; returnAssumptions: ... }):
    Scenario   // app-layer pure fn; base plan edits → Phase 3 (spec's perYearOverrides
               // is explicitly deferred; engine Scenario has no field for it)
  ```
  Every field is an *override on a base config* (`active` = the working scenario shown
  on the Plan view; `undefined` field = inherit). Defaults come from constants in
  `apps/web/src/domain/defaults.ts` (equity 5% / bond 2% / cash 0% real — spec §4 presets;
  withdrawalOrder `["tfsa","nonreg","rrsp"]` — spec §4 default).
- **Workspace model:** one IndexedDB workspace containing the plan(s) + scenarios, per the
  spec's `PlanFile`:
  ```ts
  interface PlanFile {
    schemaVersion: number;            // starts at 1
    plans: [{ meta: { id: string; name: string; updatedAt: string }, plan: Plan }];
    scenarios: ScenarioDelta[];       // app-layer; engine Scenario derived at run time
    baseScenario?: ScenarioBase;      // persisted working settings; legacy files use defaults
  }
  ```
  Phase 2 UI edits exactly one active plan (kept at `plans[0]`; list management UI is
  Phase 3). Export/import is one JSON file per workspace.
- **ID generation:** `crypto.randomUUID()` for ids; deterministic in tests via injected
  ids (form layers accept an optional id).
- **Money display:** `Intl.NumberFormat("en-CA", { style: "currency", currency: "CAD",
  maximumFractionDigits: 0 })` in tables; 2-decimals in detail expansion.
- **Never-NaN rule (spec §6):** before any chart or table consumes a number, route through
  `fmtMoney.ts` helpers which render `—` for non-finite values; projection guards
  `summary.success === false` with the fail banner.

## 4. Integration contract (written in T1/T2, consumed by every lane)

A single file `apps/web/src/store/api.ts` publishes what lanes B–E may import. Signatures
are frozen by T2's commit; later changes require captain sign-off + all-lane re-review.

```ts
// app types (src/domain/types.ts)
export interface PlanMeta { id: string; name: string; updatedAt: string }
export interface Workspace { meta: PlanMeta | null; plan: Plan; scenarios: ScenarioDelta[]; baseScenario?: ScenarioBase }
export type RunId = string;
export interface RunRecord {
  id: RunId;
  planId: string;
  scenarioId: string | null;      // null = base scenario
  result: SimulationResult;        // deep-frozen copy; never mutated
  createdAt: string;
}

// pure domain (src/domain/run.ts) — no React, unit-testable without DOM
export function resolveScenario(delta: ScenarioDelta | null, base: ScenarioBase): Scenario;
export function runDeterministic(plan: Plan, scenario: Scenario): SimulationResult;

// ScenarioBase = the Plan-view working scenario config (declared in domain/types.ts):
// { retirementAge: number; returnAssumptions: { equity: number; bond: number; cash: number };
//   withdrawalOrder: AccountType[] } — resolveScenario layering: delta override > base > defaults.

// exports (src/storage/exportImport.ts) — pure JSON transform, I/O injected
export function buildPlanFile(w: Workspace): PlanFile;
export function parsePlanFile(json: unknown): { ok: true; workspace: Workspace } |
                                            { ok: false; errors: string[] };

// persistence (src/storage/db.ts)
// Rev 2: load()/restore() return a discriminated recovery shape; snapshot()/restore()
// power destructive-import undo and corrupt-load recovery (Task 3's normative order).
export interface LoadOutcome {
  kind: "loaded" | "fresh";        // existing workspace | clean first run
  workspace: Workspace;
}
export interface RecoveryOutcome {
  kind: "recoverable";             // raw row failed validation
  offered: Workspace | null;       // newest backup, if any (restore() re-offers too)
}
export interface StorageProvider {
  load(): Promise<LoadOutcome | RecoveryOutcome>;
  save(w: Workspace): Promise<void>;
  snapshot(reason: string): Promise<void>;       // FIFO cap 3, oldest evicted
  restore(): Promise<Workspace | null>;          // newest backup, or null
  readRawRow(): Promise<unknown>;                // verbatim recovery download
  runExclusive<T>(op: (provider: StorageProvider) => Promise<T>): Promise<T>;
}
export const storage: StorageProvider;           // IndexedDB-backed singleton

// actions (src/store/actions.ts) — discriminated union consumed by useReducer
export type Action =
  | { type: "plan/setProfile"; patch: Partial<Plan["profile"]> }
  | { type: "plan/addItem"; section: SectionKey; item: unknown /* typed per section */ }
  | { type: "plan/updateItem"; section: SectionKey; id: string; patch: Record<string, unknown> }
  | { type: "plan/removeItem"; section: SectionKey; id: string }
  | { type: "scenario/add" | "scenario/update" | "scenario/remove"; delta: ScenarioDelta }
  | { type: "run/store"; record: RunRecord }
  | { type: "workspace/loaded"; workspace: Workspace };
```

Component-level rules (checked at review): views never call `simulate` directly — they dispatch
`run/*` or call `runDeterministic` through the store's memoized selector; sections of the
plan map `SectionKey = "accounts" | "assets" | "debts" | "incomes" | "expenses" |
"savingsPolicy"`; every list item key uses `item.id` (ids are stable across edits).

### Task 3 (Lane B): IndexedDB persistence + sample plan

**Files (exclusive to lane B):**

  schema validation, `db.ts` keeps the raw row in place and `load()` resolves the

### Task 4 (Lane B): Versioned JSON export / import

**Destructive-import contract (order is normative):**
1. **Parse + validate** (`parsePlanFile`) — pure, no state touched, NO backup taken;
   failures render the errors array verbatim and the flow ends.
2. **Preview** — filename, plan name, profile (age/endAge), scenario count, imported
   `schemaVersion`, validation status; buttons "Replace workspace" / "Cancel".
3. **Confirm** — the confirm message names exactly what is destroyed: current plan name
   + its updatedAt + scenario count.
4. **Snapshot** — `storage.snapshot("pre-import")` of the CURRENT workspace (never skips:
   even a corrupt current row is preserved rather than lost at the moment of swap).
5. **Swap** — replace the live workspace, autosave, re-render; success toast offers
   **"Restore previous"** (calls `restore()`, swaps back; single-level undo — only none/
   the newest backup is offered, and restoring is itself undoable by importing again).
- Future `schemaVersion` (`> SCHEMA_VERSION`) → hard block with "saved with a newer
  version of BudgetTool" plus a "Copy JSON for inspection" affordance (raw text, no
  interpretation attempt). No silent best-effort load.
- In-app destructive actions (scenario delete, plan item remove) keep plain confirm
  dialogs — they do NOT write backups; the backup store stays import/recovery-focused.

**Files:** `apps/web/src/storage/exportImport.ts`, `apps/web/src/content/planFileUi.ts`
(download/upload helpers, injected `document` use only here — the pure transform in
`exportImport.ts` stays DOM-free and unit-tested without jsdom).
- Tests: roundtrip `buildPlanFile(parsePlanFile(json).workspace)` equals original —
  **including the optional `AccountPlan.bookValue` field when present on a non-reg
  account** (set one on the test fixture so round-trip proves the field survives
  export/import/migration); stale `schemaVersion` upgrades via `migrations.ts`; unknown
